# Raahi Learning V1.3 — AI Builder v2 Screen ↔ Backend Contract + Permission Symmetry Audit

Status: **RETROFIT AUDIT COMPLETE — FINDINGS FROZEN, NO PRODUCT-DOMAIN REDESIGN IMPLIED.**

This is the mandatory AI Builder Cheat Code v2 retrofit gate for the existing V1.3 implementation. It audits the frozen canonical route inventory against the current live frontend and deployed DEV RPC/authorization model.

## Executive result

- The core domain model remains valid; no Account/Learner/Class/Enquiry/Test/Ads redesign is indicated.
- Most route contracts are symmetric and server-authorized.
- The audit found a finite set of cross-layer integration/test gaps that must be closed before the walking-skeleton gate.
- The existing server-side authorization remains protective: the main capability mismatches expose unusable controls, not extra database authority.

## Shared authenticated boot contract

Every signed-in live session begins from `list_public_locations()` + `get_my_account_context()`, then refreshes recipient/private projections (`get_my_classes`, `get_my_enquiries`, `get_my_conversations`, `get_my_learning_requests`, `get_my_class_invitations`, `get_my_notifications`, `get_my_saved_items`) and only then loads capability-scoped teacher/organization/manager/platform/ads projections. Realtime only invalidates/refetches.

## Permission-symmetry findings

### S1 — Organization route guards are too coarse
`roleAuthorized('institute')` becomes true for any Organization `manage_*` capability, while route guards then treat the whole Institute workspace as available. The database correctly enforces individual capabilities such as `manage_profile`, `manage_teaching_options`, `manage_classes`, `manage_members`, and `manage_ads`. Therefore an Ads-only or Classes-only member can see unrelated edit/manage controls that the server later rejects. **Classification: integration/UX defect; no authorization bypass.**

### S2 — Organization Class teacher picker symmetry is now correct
The earlier `manage_classes` vs `get_organization_members` mismatch is closed by `get_eligible_organization_class_teachers`. A `manage_classes` actor can obtain exactly the teacher choices required by `create_class` without gaining the broader member directory. **Classification: PASS.**

### S3 — Learner/guardian Test symmetry is correct
Self-access learner gets definition/attempt commands. Managing guardian receives `get_test_oversight` only and cannot start/save/submit the learner attempt. **Classification: PASS.**

### S4 — Contextual messaging symmetry is correct
`get_my_conversations` lists only authorized Enquiry/Class contexts; opening the row calls the existing thread projection, which rechecks current authority. **Classification: PASS.**

### S5 — Safety actions remain independent of phone freshness
Report/Block and existing contextual messaging are not phone-freshness gates. The database remains authoritative. **Classification: PASS.**

## Finite retrofit findings to close before walking skeleton

1. **Teacher members route:** implement the missing live `teacher-members` renderer from `get_teacher_class_management`, then add action/render assertions.
2. **Community report direct route:** make `community-report` carry/resolve a Community target or remove the redundant direct route; it must never silently report the current Class.
3. **Route inventory:** add `community-post` to canonical route metadata/route audit (or formally eliminate it in favor of another canonical route).
4. **Organization capability-aware UI:** route/CTA visibility must reflect exact capabilities. Server checks remain unchanged.
5. **Notification navigation:** notification payload already contains context IDs, but `notifications` currently supports only “Mark read”; add a safe destination resolver that rechecks authorization on open.
6. **Private invite OAuth hardening:** do not carry learner/staff bearer invite tokens inside the Google OAuth `redirectTo` query. Preserve locally/through a safer handoff and clear the visible query before OAuth.
7. **Phone-trust interruption/resume:** the 1020/1021 server model exists, but the frontend still needs the real hosted-Auth OTP proof and exact-action resume seam. This is a known external-technology gate, not a domain defect.

## Test-oracle corrections required

- Render tests must assert the expected page contract, not merely “has a heading/no overflow.” That is why `teacher-members` falsely passed via the generic fallback.
- Route inventory tests must compare **reachable routes vs declared canonical routes** in both directions.
- Capability tests need synthetic Accounts with **one Organization capability at a time**, not only an all-powerful fixture member.
- Notification tests must assert destination behavior in addition to row creation/read.
- Community safety tests must assert the exact target type/id submitted.

## Gate decision

**Do not restart the domain/database design. Do not proceed to broad new feature work yet.** Close the seven finite retrofit findings above, then run the AI Builder v2 side-effects matrix and one real walking-skeleton E2E journey. After those pass, continue only by vertical slice.
